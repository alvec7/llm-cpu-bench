# Легкие LLM на CPU: код и данные

Код, датасеты и сырые результаты к серии статей на Хабре о локальных моделях на VPS без видеокарты.

- Часть 1: [Легкие LLM на CPU: что реально умеет недорогой VPS с Ollama](https://habr.com/ru/articles/1103894) – 4 vCPU, 4 ГБ RAM.
- Часть 2: [Легкие LLM на CPU, часть 2: какую модель ставить на VPS без видеокарты](https://habr.com/ru/articles/1108600) – 5 vCPU, 8 ГБ RAM, российские модели 8-10B.

## Стенд

VPS у [Justhost.ru](https://justhost.ru) с шаблоном Ollama: Intel Xeon Gold 6148, Ubuntu 24.04, swap 4 ГБ, Ollama 0.35.0 в Docker (llama.cpp 161755f29). В первой части – 4 vCPU и 4 ГБ RAM, во второй – 5 vCPU и 8 ГБ. Для d1-2B поднималась отдельная Ollama 0.40.15.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `runner.py` | Основной раннер: гоняет сценарий по списку моделей через API Ollama, считает качество, время, токены в секунду, память и обмен со swap |
| `scenarios/<id>/` | Сценарий = `dataset.json` (примеры и эталоны) + `scenario.py` (промпт, JSON-схема ответа, функция оценки) + `results/<tag>/` (ответы моделей по примерам и `summary.json`) |
| `report.py`, `rescore.py`, `validate_gold.py` | Сводная таблица, пересчет оценок без повторного прогона, проверка эталонов |
| `loadtest.py`, `loadtest2.py` | Нагрузочные тесты (1, 2, 4 клиента; с кэшем промпта и без) |
| `scripts/` | Сценарии прогонов: конфигурации Ollama A/B/C, повтор на 8 ГБ, повтор 326 и замер без кэша, проверка `LLAMA_ARG_CACHE_RAM` |
| `steallog.py` | Запись steal раз в секунду |
| `gen_s1big.py` | Генерация и разметка расширенного набора для классификации (нужен OpenAI-совместимый API, см. `apirunner.py`) |
| `d1bench.py`, `d1_analyze.py` | Прогон decision-модели d1-2B через `/v1/systemone` и анализ: точность, McNemar, калибровка, пороги |
| `results/` | Результаты нагрузочных тестов, лог steal (`steal.jsonl.gz`), слепая ручная разметка 50 обращений |
| `models.txt` | Модели первой части |

Сценарии: `01_classification` (20 обращений), `01b_class_big` (326 обращений), `02_sentiment`, `03_extraction` и `03b_extraction_v2`, `04_summary`, `07_direct_ads`, `08_normalize`, `09_rag`.

Теги результатов: `base` и `lfm-think` – первая часть (4 ГБ); `ram8` – вторая часть (8 ГБ); `ram8-r2` – повтор прогона на 326; `ram8-nocache50` – 50 обращений с уникальной меткой в начале промпта, без кэша; `d1-2b` – decision-модель.

## Как запустить

Нужен Python 3.10+ без внешних зависимостей и Ollama с нужными моделями.

```bash
# адрес Ollama; без переменной раннер ищет контейнер ollama-ollama-1 или берет 127.0.0.1:11434
export OLLAMA_URL=http://127.0.0.1:11434

# классификация 326 обращений двумя моделями
python3 runner.py scenarios/01b_class_big --tag mytest \
  --models qwen3.5:4b,hf.co/Vikhrmodels/QVikhr-3-4B-Instruction-GGUF:Q4_K_M

# то же без кэша промпта на случайных 50 обращениях
python3 runner.py scenarios/01b_class_big --tag mytest-nocache --sample 50 --unique-prefix --models qwen3.5:4b

# сводка
python3 report.py scenarios/01b_class_big --tag mytest
```

Условия у всех моделей одинаковые: один промпт, ответ по JSON-схеме, temperature 0, seed 42, режим рассуждения выключен, в памяти одна модель, перед замером прогрев посторонним запросом.

## Важно

- Обращения, отзывы, документы и база знаний синтетические, сгенерированы и размечены моделями. Как проверялась разметка, описано во второй части.
- На вашем железе и ваших данных цифры будут другими. Репозиторий нужен, чтобы проверить методику и повторить замеры, а не чтобы переносить проценты как есть.
